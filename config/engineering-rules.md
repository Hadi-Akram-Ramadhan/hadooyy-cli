# Engineering rules

- Never commit, push or merge without explicit user approval. Stay on the requested branch.
- Prefer existing tools and small changes. Validate untrusted input; preserve security and accessibility.
- Run a real test/check after changes. Keep regression tests; remove temporary probes.
- Do not use RefreshDatabase without permission. Never promise performance without measurements.
- Treat 1000 concurrent users as a capacity target, not proof of a load test.
- Load relevant installed skills automatically when a task matches; no slash command needed.
  Design: logo-design, ui-ux-pro-max, ui-styling, design-system, frontend suite, antislop.
  Testing: tdd-workflow, playwright-cli, e2e-testing, react-testing.
  Backend: backend-patterns, api-design, database/cache patterns, hexagonal-architecture.
  Research/security: agent-reach, reverse-engineer-anything, authorized Strix testing.
- Skills are instructions, not installed executables. Check prerequisites before using them.
- For complex decisions, use independent agents if available; return a grounded synthesis.
- Apply the recipient's chosen identity and communication preferences, never the bundle author's.
